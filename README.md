# Squid Proxy Control Panel

لوحة ويب عربية لإدارة Squid على خادم VPS، مع مثبت تفاعلي، حساب مدير منفصل، وإدارة المستخدمين وسياسات الوصول من المتصفح. يعتمد المشروع على حزمة Squid من مستودعات Ubuntu/Debian ولا يعيد توزيع Squid نفسه.

> **الأمان الافتراضي:** يتوقف Squid أثناء إعداد الحزمة، ثم يُهيّأ بسياسة رفض كاملة. لا يبدأ قبول اتصالات البروكسي إلا بعد إضافة حساب مصادقة من اللوحة. البروكسي يتطلب اسم مستخدم وكلمة مرور، ولا يتحول إلى open proxy بدون مصادقة.

## الميزات

- صفحة تثبيت تفاعلية تسأل عن منفذ لوحة التحكم واسم المدير وكلمة مروره. إدخال كلمة المرور مخفي، وتُخزن مجزأة لا كنص صريح.
- واجهة عربية متجاوبة مع تسجيل دخول محمي، حماية CSRF، تحديد لمحاولات الدخول، جلسات موقعة، وترويسات أمان.
- إدارة حسابات Squid: إضافة مستخدم، تغيير كلمة المرور، الحذف، وتطبيق فوري للإعدادات. تُحفظ كلمات مرور الوكيل بصيغة bcrypt التي يدعمها `htpasswd` وSquid.
- إعداد منفذ البروكسي (يستمع على `0.0.0.0`)، منافذ الوجهة المسموحة، منافذ `CONNECT`، قائمة نطاقات اختيارية، وقائمة عملاء IP/CIDR اختيارية.
- منع طلبات البروكسي إلى loopback وlink-local والشبكات الخاصة لتقليل مخاطر الوصول إلى خدمات VPS الداخلية.
- فحص صياغة إعداد Squid قبل التطبيق؛ وإذا فشل تطبيق/إعادة التشغيل يحاول استرجاع الإعداد السابق ويوقف Squid fail-closed حتى لا يبقى خادم بمصادقة أو إعداد قديم.
- عرض حالة الخدمة وسجل Squid وآخر عمليات الإدارة، وتصدير إعدادات غير سرية دون كلمات المرور أو تجزئاتها.
- مساعد root محدود بقائمة أوامر ثابتة، بدل تشغيل لوحة الويب بصلاحيات root أو تمرير أوامر shell.

## المتطلبات المدعومة

- VPS يعمل بـ Ubuntu أو Debian، يستخدم `apt` و`systemd`.
- تشغيل المثبت كمستخدم `root` أو عبر `sudo`، واتصال إنترنت لتنزيل حزم النظام وتبعيات Python.
- تُدار قواعد جدار الشبكة السحابية وUFW يدويًا؛ لا يعدّل المثبت قواعد الجدار تلقائيًا.

## التثبيت

اتصل بالخادم عبر SSH ثم نفّذ:

```bash
git clone https://github.com/alrufaaey-yahoo/squid-proxy-control-panel.git
cd squid-proxy-control-panel
sudo bash install.sh
```

سيطلب المثبت:

1. منفذ لوحة التحكم (افتراضيًا `8080`، ويجب أن يكون بين 1024 و65535 وألا يساوي منفذ Squid الافتراضي `3128`).
2. اسم مستخدم المدير.
3. كلمة مرور المدير مرتين. يجب أن تكون 12 محرفًا على الأقل، ولا تظهر على الشاشة.

بعد اكتمال التثبيت تظهر وصلة بالشكل `http://SERVER_IP:PANEL_PORT`. افتحها وسجّل الدخول ببيانات المدير. في التثبيت الجديد يظل البروكسي مغلقًا إلى أن تضيف مستخدمًا من قسم **مستخدمو Squid**.

إذا وجد المثبت قاعدة بيانات من محاولة سابقة أو تثبيت قائم، سيطلب تأكيد المتابعة. عند الموافقة يحتفظ بحسابات مستخدمي البروكسي وسياساتهم، ويحدّث منفذ اللوحة وبيانات دخول المدير التي تدخلها أثناء التثبيت.

## أول إعداد للبروكسي

1. من اللوحة أضف اسم مستخدم وكلمة مرور للبروكسي (12 محرفًا على الأقل، وبحد أقصى 72 بايتًا UTF-8 لتجنب اقتطاع bcrypt).
2. من **إعدادات الوكيل** اختر منفذ Squid، مثل `3128`. لا تستخدم منفذ لوحة التحكم نفسه.
3. أبق منافذ الوجهة على `80,443` ما لم تكن لديك حاجة موثوقة أخرى. يجب أن تكون منافذ `CONNECT` جزءًا من القائمة.
4. اختياريًا أدخل نطاقات مسموحة، سطرًا لكل نطاق (`example.com` أو `.example.org`)، أو عناوين عملاء CIDR. القائمة الفارغة لا تقيّد الوجهات/العناوين بهذه الطريقة.
5. احفظ. يفحص النظام صياغة Squid ثم يطبق التهيئة ويعيد تشغيل الخدمة.

مثال اختبار من جهاز العميل (استبدل القيم، واستخدم متغيرات بيئة لتجنب وضع كلمة المرور في الأمر المحفوظ):

```bash
export PROXY_USER='اسم-المستخدم'
read -rsp 'Proxy password: ' PROXY_PASSWORD; echo
curl --proxy "http://SERVER_IP:3128" --proxy-user "$PROXY_USER:$PROXY_PASSWORD" https://example.com/
unset PROXY_PASSWORD
```

## الجدار الناري وشبكة الوصول

كلا المنفذين يستمعان على جميع واجهات IPv4 كما طلبت، لكن عليك منع الوصول غير الضروري في جدار مزود VPS وUFW. لا تفتح المنفذين للعالم ما لم يكن ذلك مقصودًا. مثال UFW مقيّد لمصدر مسؤول واحد وعملاء معروفين:

```bash
sudo ufw allow from ADMIN_PUBLIC_IP to any port PANEL_PORT proto tcp
sudo ufw allow from TRUSTED_CLIENT_CIDR to any port SQUID_PORT proto tcp
sudo ufw status
```

استبدل القيم الفعلية. لا تستخدم `0.0.0.0/0` بلا سبب. إذا غيّرت منفذ Squid من اللوحة، حدّث قاعدة الجدار كذلك. يمكن فرض النطاقات وعناوين العملاء أيضًا من اللوحة، لكن الجدار الناري طبقة مستقلة مطلوبة.

## تحذير النقل والتشفير

تسجيل دخول اللوحة وواجهة البروكسي الافتراضية يستخدمان HTTP. مصادقة Squid الأساسية ترسل بيانات الاعتماد بترميز قابل للاستعادة، وليست تشفيرًا بين جهاز العميل والخادم. **لا تستخدم هذا الاتصال عبر شبكة غير موثوقة مباشرة.** قيّد منافذ الوصول إلى عناوين معروفة، واستخدم VPN أو نفقًا مشفرًا بين العميل والخادم. للوحة الويب، ضع Nginx أو وكيلًا عكسيًا مع TLS، امنع الوصول العام المباشر إلى منفذ اللوحة في الجدار، ثم اضبط `PANEL_COOKIE_SECURE=true` في `/etc/squid-panel/panel.env` ونفّذ:

```bash
sudo systemctl restart squid-panel
```

لا يضيف هذا المشروع شهادة TLS تلقائيًا ولا يهيئ `https_port` لـ Squid.

## إدارة الخدمة والأعطال

```bash
sudo systemctl status squid squid-panel
sudo journalctl -u squid -n 100 --no-pager
sudo journalctl -u squid-panel -n 100 --no-pager
```

إعادة تشغيل اللوحة أو Squid لا تمسح قاعدة البيانات. إذا رفض Squid التهيئة الجديدة، افحص الرسالة الظاهرة في اللوحة وسجل الخدمة. المساعد الجذري هنا هو `/usr/local/sbin/squid-panel-helper`؛ صلاحيات `sudo` محصورة بأربع عمليات ثابتة (`status`, `logs`, `apply`, `restart`).

## النسخ الاحتياطي والتحديث

توقف اللوحة أولًا ثم انسخ قاعدة البيانات وملف البيئة وإعداد Squid إلى مكان آمن خارج الخادم، واحمِ النسخة لأنها تتضمن تجزئات بيانات الاعتماد:

```bash
sudo systemctl stop squid-panel
sudo install -d -m 0700 /root/squid-panel-backup
sudo cp -a /var/lib/squid-panel/panel.sqlite3 /etc/squid-panel/panel.env /etc/squid/squid.conf /etc/squid/passwd /root/squid-panel-backup/
sudo systemctl start squid-panel
```

للتحديث: خذ نسخة احتياطية، حدّث نسخة Git في `/opt/squid-proxy-panel` أو انشر الإصدار الجديد بالطريقة الإدارية المعتمدة لديك، ثم ثبّت متطلبات `requirements.txt` في البيئة الافتراضية وأعد تشغيل `squid-panel`. عند تشغيل المثبت على قاعدة موجودة سيطلب تأكيدًا، ولن يغيّر إعدادات Squid أو مستخدمي البروكسي؛ سيعيد فقط تعيين بيانات دخول مدير اللوحة ومنفذها إلى القيم التي تدخلها.

## حدود المشروع

المشروع مُعد لإدارة Squid الأساسي: منفذ استماع IPv4 واحد، حسابات محلية، مصادقة أساسية، منافذ وجهة، قيود نطاق/IP، حالة وسجلات. لا يقدم تعدد عقد، تدوير عناوين خروج، مراقبة استخدام تفصيلية، شهادات TLS لـ Squid، أو إدارة إعدادات Squid التعسفية. لا يدعم مثبتًا رسميًا لأنظمة RHEL/CentOS أو الحاويات. جرّب التثبيت على VPS تجريبي قبل الإنتاج.
